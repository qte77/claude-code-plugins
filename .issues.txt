=== ISSUE 126
## Reasoning

Cross-session continuity is a gap in cc-meta workflows. The orchestration skills (handing-off-session, summarizing-session-end) exist but are never triggered automatically. Users forget to run them, losing context between sessions.

A lightweight Stop hook reminder would nudge the user without costing tokens on every stop.

## Goals

- Remind user to run `/handing-off-session` when session ends with in-progress work
- Zero token cost (no LLM call, just inject context via hookSpecificOutput)
- Non-blocking — reminder only, not auto-summary
- Optional — users can disable via settings.local.json

## Implementation suggestion

Add a Stop hook to cc-meta plugin's `hooks/hooks.json`:

```json
{
  "hooks": {
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "echo '{\"hookSpecificOutput\":{\"hookEventName\":\"Stop\",\"additionalContext\":\"Session ending — consider /handing-off-session if work is in progress.\"}}'",
            "timeout": 5
          }
        ]
      }
    ]
  }
}
```

### Alternatives considered

| Option | Pros | Cons |
|--------|------|------|
| **Reminder hook** (recommended) | Zero cost, non-blocking | Easy to ignore |
| **Auto-summary on Stop** | Automatic, no user action needed | Token cost every stop, even trivial sessions |
| **Prompt hook with LLM check** | Smart — only fires when work is in progress | Token cost, latency, overkill |

- **Document the resolution order** (env pin > per-call > frontmatter > main) in CONTRIBUTING/plugin-authoring docs so authors know when their `model:` field is dead.
- **Maintainer env decision**: keep `CLAUDE_CODE_SUBAGENT_MODEL` pinned (cheap-by-default, no per-call upshift possible) vs remove it (per-call/frontmatter selection works; fan-out defaults to the main model). Currently pinned to `claude-sonnet-5`.
